# Architecture — Phase 1

## Decision

Phase 1 uses a static normalized snapshot generated by a local Node script and rendered by a React/Vite dashboard. This keeps the dashboard read-only and avoids exposing filesystem APIs to the browser.

## Flow

```text
Hermes safe metadata + mission registry
        ↓
scripts/generate-snapshot.mjs
        ↓
public/data/stronghold-snapshot.json
        ↓
React dashboard
```

## Modules

- Snapshot collector: safe metadata discovery and normalization.
- Dashboard shell: mission-control layout and status panels.
- Engineering roster: Igris and specialist visibility.
- Agent inventory: profile/wrapper/skill/cron summary.
- Mission board: planned/active/blocked/review/complete lanes.
- Cron monitor: safe schedule metadata.
- Safety panel: read-only locks and review status.

## Data contract

See `src/types.ts` for the TypeScript contract. The browser consumes only the generated JSON snapshot.

## Phase 2 boundary

Any write-capable operation, automation, command execution, or profile/cron mutation requires separate Phase 2 authorization and a new architecture review.
